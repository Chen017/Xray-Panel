## 已修复的问题

| 级别 | 问题与触发条件 | v1.3.0 行为 / 回归证据 |
| --- | --- | --- |
| P2 | 解除最后一个落地关联后，`refreshLinks` 跳过节点，遗留同步错误继续阻止设备授权自动部署；心跳的 `Object.assign` 也不会删除这些字段 | 清除关联状态，重新读取节点对象；HTTP 测试确认同一次心跳可以领取 `device-sync` 任务 |
| P2 | 停止的 Compose 容器也会被发现，但备份使用 `docker exec`，导致无法更新 | 使用一次性离线辅助容器备份停止的节点；更新失败后恢复旧镜像及数据库，保持停止状态 |
| P2 | 卸载保留数据卷后重装，新版本失败只移除容器，没有备份或恢复旧数据库 | 按保存的旧版本为保留卷创建一致性快照，失败恢复数据库、所有权和环境配置，保留原版本状态 |
| P2 | SQLite 快照写入只有 32 MiB 的容器 `/tmp`，大数据库无法更新，失败前的快照也未清理 | 在数据卷内创建临时快照，输出后在 `finally` 清理；真实 WAL 数据库超过 32 MiB 的备份与恢复内容检查通过 |
| P2 | 管理器复制中断后，版本目录或 `lifecycle.py` 的存在被当作缓存完整，重新运行仍会执行残缺安装 | 暂存完整目录并写入完成标记，再原子发布；旧的未完成缓存会重建，发布失败恢复旧目录；Python 与真实 Bash 重试测试覆盖 |
| P2 | 检测结果数组含 `null` 等无效项时，读取 `r.id` 抛异常，回滚整个 Agent 心跳 | 跳过无效项，接受同批合法结果，不因无效条目中断心跳 |
| P3 | 告警页面沿用最后一次上报的结论；测点周期不同且大陆证据已过期时，仍显示已确认告警 | 每次查询重新计算有效样本和门槛；保留历史事件状态，但标明当前证据不足 |
| P2 | Telegram 返回合法 JSON `null` 时，在解析后的 `data.ok` 访问中抛异常，发送状态停留在租约等待 | 非对象 JSON 返回结构化失败，继续走正常退避流程，不泄露响应内容或 Token |

落地状态、无效检测结果、证据过期与 Telegram 响应的新增回归测试先在旧逻辑上复现失败，再应用修复。生命周期的 systemd / Docker 操作在隔离测试中模拟；SQLite 备份代码本身由真实 Node SQLite 执行。

本地验证：Node 57/57、Linux Agent 20/20、生命周期 11/11、真实 Xray/Mihomo 集成 14/14；TypeScript、生产构建与解压发布包启动检查通过。完整说明见 [test-report.md](test-report.md)。
