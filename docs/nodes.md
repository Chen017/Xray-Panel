# 节点接入与管理

先完成 [Panel 部署](1panel.md) 与 [Cloudflare 保护](cloudflare.md)。Panel 安装在建站 VPS，Agent 安装在每一台需要管理的节点 VPS；两者分别更新。

## 1. 添加节点并接入 Agent

1. 在「节点管理」添加节点，填写备注。客户端 IPv4 / IPv6 地址可自动检测；NAT 公网映射、DDNS 等情况可手动设置。
2. 在接入窗口填写**该 VPS** 的 Cloudflare Service Token，复制完整安装脚本，在目标 VPS 的 root Bash 终端执行。凭据必须属于 Agent 域名的 Service Auth 策略。
3. 等待节点在线并导入当前配置。接入本身不会重装 Xray，也不需要先点部署。

**Agent 可以独立安装，不要求预先安装 Xray Script。** 没有 Xray 时，在节点管理中选择对应安装操作，再等待 Agent 返回配置。

已有 `xray-panel` 管理器时，也可执行 `xray-panel agent install` 并粘贴面板生成的接入信息。Script v2.7.10 起可从「杂项管理 → 集中管理 / Panel Agent」或 `xray agent install` 接入；入口会检查已有 Agent 并保留身份及凭据。

## 2. 编辑、预览与部署

在节点的「管理」页导入 VPS 当前配置，再编辑基础参数、XHTTP、分流规则、互联与防火墙。保存草稿只影响面板；确认预览后点击部署，才会创建 Agent 任务。

Agent 先校验配置，再应用服务与防火墙；失败时沿用 Script 的事务回滚。任务成功后，面板才发布对应订阅。任务结果和错误输出可在「部署与任务」查看。

通过 SSH / Script 修改过配置后，先在面板重新导入，避免旧草稿覆盖外部修改。自动地址检测失败保留最后有效地址；客户端地址更新本身不会重启 Xray，关联落地地址变化则走正常部署任务。

## 3. 统一节点名称与顺序

- **名称**：在节点管理页点击备注旁的「订阅名称」，设置基础名称或各文件、出口、模式的完整名称。所有授权设备共用，详见 [订阅名称说明](mihomo.md#4-自定义名称与顺序)。
- **顺序**：在「节点管理」首页的「所有节点」列表点击「节点排序」，上下移动并保存。该列表、所有设备订阅、预览与 VLESS 导出使用同一顺序。

排序包含所有节点，包括停用和尚未发布的节点；设备订阅仍只包含其已授权且已部署成功的条目。同一节点的文件、出口和模式连续排列。新节点追加到末尾，节点重新发布时保留原位置；「恢复添加顺序」按创建时间恢复。

旧的设备独立排序不再参与导出。名称或顺序保存后，所有设备刷新 provider 即可生效，无需部署 Xray 或更新 Agent。

## 4. 授权设备与生成订阅

到「设备与订阅」生成设备 age 密钥，选择节点、出口与连接模式。保存仅显示一次的 Token 和私钥配置，等待独立 UUID 部署成功，再按 [Mihomo / Clash Verge Rev 指南](mihomo.md) 合并本地配置。

撤销 Token 会立即停止该设备拉取；VPS 的 UUID 删除需要 Agent 在线完成同步。控制中心或节点离线时，已经下载到客户端的配置不会被远程抹除。

## 更新与排错

目标 VPS 运行 `xray-panel agent status` / `xray-panel agent logs` 查看状态与日志，运行 `xray-panel agent update` 更新。也可使用已安装 Script 的 `xray agent` 对应命令。更新 Panel 不会自动更新各节点 Agent。

| 现象 | 检查 |
| --- | --- |
| 节点一直离线 | Agent 服务、Agent 域名、Service Token 与对应 Access 策略 |
| 同步返回登录页 / 403 | [Cloudflare 机器认证与排错](cloudflare.md#troubleshoot) |
| 预览提示外部配置变化 | 先导入 VPS 当前配置，再重新编辑部署 |
| 已授权但订阅没有节点 | Agent 部署结果、节点发布开关、地址及授权模式 |
| 排序保存提示列表已变化 | 关闭排序窗口，重新打开后操作 |

更新、卸载与备份命令见 [README](../README.md)。
