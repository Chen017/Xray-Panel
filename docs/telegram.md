# Telegram 告警

在「安全与设置 → Telegram 与网络告警」配置。Panel 与相关 Agent 使用 v1.2.0 或更新版本，推荐含审查修复的 v1.3.0；两者分别更新。

## 检测什么

| 检测 | 条件与含义 |
| --- | --- |
| SNI / TLS | 节点自己的 Agent 检查对应地址族的 DNS、证书、TLS 1.3 和 h2；不代表实际代理链路已经验证 |
| 国内 IP:端口 | 默认至少两个大陆测点连续三轮失败，且境外对照近期成功，才报告“疑似国内网络阻断” |

没有真实大陆测点时不能判断国内阻断；海外向国内发起连接也不能代替这一方向的检测。对照结果仍不能证明一定是 GFW，路由、来源限制等也可能产生类似现象。

## 配置步骤

1. 在 Telegram 的 BotFather 创建 Bot；向 Bot 发送 `/start`，或把它加入允许发消息的群组。可通过 [getUpdates](https://core.telegram.org/bots/api#getupdates) 返回的 `message.chat.id` 获取数字 Chat ID；话题 ID 对应 `message_thread_id`。
2. 在面板保存 Bot Token、Chat ID 和可选话题 ID。Token 加密保存，不回显；留空保留原值，清除时先关闭启用开关，再勾选清除。
3. 点击「向已保存的 Chat 发送测试通知」，到 Telegram 确认实际收信。成功回执表示 API 接受，最终聊天收信仍需自己检查。
4. 若需要国内阻断告警，接入真实大陆 Agent 与境外对照 Agent，在表单分别选择；只有 SNI 检查时可不选这些测点。仅作为测点的机器不必安装 Xray。
5. 确认测点位置与网络方向，启用检测并保存。尽量分布在不同地区 / 运营商，不把同一机器的两个接入记录当作独立线路。

每个测点默认每 300 秒检查一批最多 8 个目标，目标多时轮询；默认连续三轮失败确认、两轮恢复确认。离线、过期、重放和目标已改变的结果不作为当前封锁证据；重新保存设置会重新取证。

## 通知与故障处理

- 状态变化时通知，持续相同故障不反复刷屏；检测不会自动改动 IP、SNI、Xray 或授权。
- 临时失败退避重试，429 遵循等待时间；401 / 403 等凭据或权限错误需修正设置。重启后继续处理持久化队列，未发送状态最长等待 24 小时。
- 回执丢失后重试可能重复送达；改变接收方会取消旧的等待通知，已经发出的请求无法撤回。
- 通知包含节点备注、目标地址和诊断类型，不包含 UUID、REALITY 密钥、订阅 Token 或 age 私钥。

若没有结果，检查启用开关、Agent 版本及在线状态；若没有国内告警，检查大陆测点数量、连续轮次和境外成功对照；若发送失败，查看页面的脱敏状态码，并核对 Token、Chat ID、话题和群组权限。

正式依赖通知前，用自己的 Bot 验证收信，并在专用测试节点验证故障与恢复。自动化模拟、真实本地 TLS 测试的范围见 [测试记录](test-report.md)，不代替真实大陆网络验收。

官方参考：[Bot 入门与 Chat ID](https://core.telegram.org/bots/tutorial)、[sendMessage](https://core.telegram.org/bots/api#sendmessage)。
