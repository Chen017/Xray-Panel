# Telegram 告警

## 先明确检测范围

SNI 由目标节点自己的 Agent 检查：按 IPv4 / IPv6 解析域名，验证公开目标地址、证书链和域名、TLS 1.3、ALPN h2。不会关闭证书校验，也不会借检测访问私网地址。它验证握手条件，不代表已经完成实际代理连接或验证站点全部 HTTP 内容。纯落地节点没有标准 REALITY SNI 时跳过此项。

国内 IP:端口检测需要你自己的中国大陆测点。默认至少两个不同的大陆 Agent 连续三轮连接失败，同时境外对照测点近期连接成功，才发送“疑似国内网络阻断”通知。仅在海外 VPS 向国内发起连接无法验证国内到节点的方向；没有大陆测点、只有一个测点但要求两个、境外也失败、结果过期或测点离线时，都不形成封锁结论。这个结果也不能证明一定是 GFW，可能与运营商路由或其他来源限制有关，不代表整个 IP 的所有端口都被封。

测点的位置由管理员声明，程序不会自动验证地理位置。建议大陆测点分布在不同地区或运营商，不能把同一台机器的两个接入记录当作独立线路证据。检查的是节点当前客户端连接地址（包括手动 NAT / DDNS 覆盖），使用普通入站端口及落地公网映射端口。

## 配置

1. 本版功能需要 Panel 与有关 Agent v1.2.0。Panel 更新与 Agent 更新分别执行，不会自动给所有 VPS 更新 Agent。
2. 将大陆/境外机器作为节点接入。可以直接使用面板提供的独立一键 Agent 脚本，不需要安装 Xray Script 或 Xray。没有 Xray 的接入记录也可选择为测点；此时没有代理配置可导入，其他节点的网络检测仍能执行。
3. 在 Telegram 的官方 BotFather 创建 Bot，保存 Token。向 Bot 发送 `/start`，或把它加入接收通知的群组。群组/频道需有发送权限；话题群可填话题 ID。Chat ID 使用数字，群组 ID 通常为负数。获取 ID 见 [Telegram 官方教程](https://core.telegram.org/bots/tutorial)。不要把 Token 发到公开聊天、URL 查询或 GitHub。
4. 面板「安全与设置 → Telegram 与网络告警」填写 Bot Token、Chat ID，选择大陆与境外测点。Bot Token 经面板数据库加密保存，页面仅显示“已保存”；留空保留原值。清除时显式打开“清除已有 Bot Token”，并先关闭启用开关。
5. 保存后点击“发送测试通知”，确认实际 Telegram 收信，再启用自动检测。通知会发出节点备注、目标地址、诊断类型和时间，不包含 UUID、REALITY 密钥、age 私钥或订阅 Token。
6. 等待 Agent 心跳。默认每个测点每 300 秒执行一批最多 8 个目标，目标多时轮询；不是保证每个节点都恰好每五分钟完成检查。单次子进程最多 5 秒，最多 4 个并行，不改变 Xray 配置、服务或防火墙。

国内与境外测点不能选同一个接入记录。默认三轮失败确认、两轮恢复确认；结果只按服务端签发的计划接收一次。地址、端口、SNI 或检测设置改变后，旧计划不作为新证据；重新保存设置会重新开始取证。超过预计巡检周期的历史样本不会当作当前证据。

## 通知行为

- 只在告警/恢复状态变化时排队，持续失败不反复刷屏。
- 发送队列加密保存在数据库中，重启后继续。临时网络错误退避重试；Telegram 429 遵循 `retry_after`。401 / 403 等凭据或权限错误停止该条重试，在页面显示发送失败；修正并保存设置后重新检测。
- 取消/过时的未发送告警不会继续送出，等待队列最长保留 24 小时。变更接收方不会把旧队列发送给新 Chat；已经发出的网络请求无法撤回。
- Telegram 回执丢失时无法承诺绝对只送达一次，重试可能产生重复；只有有效成功回执才标记发送成功。恢复发生于发送途中时，也会在告警确认后处理恢复通知。
- 检测不自动变更 IP、SNI、DNS、Cloudflare、Xray 或订阅授权。

API 使用 Telegram 官方 `https://api.telegram.org/bot<TOKEN>/sendMessage`，HTTPS JSON POST。Token 必须出现在 Telegram 指定的路径格式中，但程序不记录该 URL、任意响应正文或包含凭据的网络异常，只保存脱敏状态码。[官方 API 与限流说明](https://core.telegram.org/bots/api#sendmessage)。

## 本地已测试与待你验收

自动测试覆盖国内测点不足、境内外共同失败、证据过期、重复回执、目标变化、SNI 故障/恢复、告警发送竞争、进程重启后的重试、429、无效凭据、加密与鉴权。使用真实本地 TLS 服务器验证证书校验、TLS 1.3、h2，以及 Telegram HTTPS JSON 报文和成功回执；没有把模拟结果说成真实 Bot 收信。

以下需要你提供真实条件，暂未执行：

- 用自己的 Bot/Chat 验证最终收信、群组或话题发送权限。
- 配置真实大陆与境外 Agent，核对测点地理位置及网络方向。
- 在你批准的测试节点模拟连接或 SNI 故障与恢复，确认实际通知。不要为了测试去破坏当前生产节点。
