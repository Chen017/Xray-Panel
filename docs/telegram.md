# Telegram 告警

在「安全与设置 → Telegram 与网络告警」配置。完整的互联告警需要 Panel 与节点现有 Agent 均更新到 v1.3.6，**不需要新增大陆或境外测点 Agent**。

## 检测方式

中转机与独立节点复用 Xray Script 的只读 `network_probe.sh`：

- 国内：连接上海移动、联通、电信三个固定目标的 TCP 80，任意一个成功就算可达。
- 境外：ping Cloudflare `1.1.1.1`、`1.0.0.1`；ICMP 不通时尝试 TCP 443，任意一次成功就算可达。
- SNI：节点 Agent 检查对应地址族的 DNS、证书、TLS 1.3 与 h2，不修改 Xray 配置。

| 国内目标 | Cloudflare | 连续失败确认后的通知 |
| --- | --- | --- |
| 全部失败 | 可达 | 疑似国内连通异常 |
| 全部失败 | 不可达 | 节点网络异常 |
| 可达 | 不可达 | 境外对照异常 |
| 可达 | 可达 | 正常；连续恢复确认后发送恢复通知 |

这是从 VPS 发出的连通检测，不能据此确认国内客户端到节点 IP / 端口被墙，也不验证完整代理链路。中转与独立节点的国内和境外检查并行、限时执行；连续失败默认 3 轮，恢复默认 2 轮，每轮默认间隔 300 秒。上表国内与境外组合不适用于落地机。


落地机**不运行国内检测**。它只检查海外 Cloudflare `1.1.1.1`、`1.0.0.1`，先尝试 ICMP，失败后用 TCP 443 兜底，任一目标可达即判定海外网络可达。Agent 在本机按当前运行配置识别落地角色，即使收到旧的国内检测计划也会拒绝执行；配置损坏、角色无法确认时也不执行国内检查。

## 中转与落地互联

v1.3.6 新增三项独立检测，**任一项**达到连续失败阈值就告警，不要求三项同时失败：

| 检测项 | 执行位置 | 目标 |
| --- | --- | --- |
| 中转 → 落地 | 中转机 Agent | 运行中互联配置里的落地地址与端口；NAT 使用外部映射端口 |
| 落地 → 中转 | 落地机 Agent | 关联中转机的公开地址与实际 Xray 入站端口 |
| 落地海外连通 | 落地机 Agent | 仅 Cloudflare 海外固定目标，绝不调用国内三网检测 |

双向互联使用限时 TCP 连接，直接从相应 VPS 发起，不经过代理、不修改配置。它检查地址和端口是否可达，不能代替 VLESS 握手、加密参数或完整代理流量测试。

检测基于 Agent 上报的**运行中配置**，不会探测尚未部署的草稿。反向关联优先使用面板绑定的落地节点；导入的手动地址也可通过落地公开地址与端口匹配。中转和落地都应接入面板并启用，且中转应有可识别的公开入站端口；未关联或无法识别端口时不会凭空猜测反向目标。地址、端口、角色或关联变化后，旧目标证据失效。

每个方向、每条落地线路分别计数，TCP 失败原因在超时、拒绝连接、DNS 失败之间变化仍算连续失败。默认失败 3 轮提醒、恢复 2 轮通知；持续失败不重复刷屏。超过 8 个检测目标会分批轮询，每条链路的确认时间相应延长，缺失或过期结果不算失败。


## 配置

1. 向 BotFather 创建 Bot，并先给 Bot 发送 `/start`，或加入允许发消息的群组。通过 [getUpdates](https://core.telegram.org/bots/api#getupdates) 的 `message.chat.id` 获取 Chat ID；话题 ID 可选。
2. 保存 Bot Token、Chat ID、间隔和失败 / 恢复轮数。Token 加密保存、不回显；留空保留已保存值。
3. 点击「向已保存的 Chat 发送测试通知」，确认 Telegram 实际收信，再启用检测。API 成功回执只表示 Telegram 接受请求。
4. 中转和落地的现有 Agent 使用 `xray-panel agent update --version 1.3.6` 更新；也可执行 `xray agent update --version 1.3.6`。新接入仍使用面板生成的一键安装脚本。Panel 升级不会代替各 VPS 的 Agent 升级，也无需重装或部署 Xray。

升级时保留原 Bot、Chat 和轮次设置，旧测点选择不再使用。支持检测的节点上线后自动取得计划、回传结果；没有新结果或结果过期时不累计失败。

## 通知规则

同类故障只在确认与恢复时通知；故障类别变化也需重新累计。临时发送失败退避重试，429 遵循 Telegram 等待时间，重启后继续处理队列；延迟通知需重新确认当前证据。回执丢失可能导致重试重复送达。

通知包含节点备注和诊断类型，不含 UUID、REALITY 密钥、订阅 Token 或 age 私钥。SNI 通知还包含目标域名。检测不会自动更换 IP、SNI 或代理配置。

没有结果先检查节点 Agent 版本和在线状态；发送失败检查页面脱敏状态码、Bot Token、Chat ID、话题和群组权限。真实 Bot 收信与公网故障恢复仍需用自己的环境验收，自动化测试范围见 [测试记录](test-report.md)。
